# VR4ALL

**Standalone VR Mod Installer** for Meta Quest. It detects connected Quest 2, Quest 3, Quest 3S, and Quest Pro headsets; each port's compatibility still depends on its author. Choose a port, select the game files from a copy you own, then install the APK and transfer the files to a USB-connected headset.

## Run the Windows app

Download the current portable Windows `.exe` from the [VR4ALL releases page](https://github.com/vr4all-standalone/vr4all-standalone/releases) and double-click it. The executable opens its own VR4ALL window; Node.js and a separate browser are not required. It is unsigned, so Windows may show a publisher warning. VR4ALL keeps settings and official APK downloads in Windows application data; your selected ROMs and local APKs remain in their original folders. The Windows build includes Android Platform Tools ADB for USB headset detection and 7-Zip for `.7z` or `.rar` conversion; Windows packages folders and loose files as ZIPs for installation. Use **Connection help** below the headset selector to set another `adb.exe` path if needed. Use **Change theme** in the sidebar to choose Graphite (the default), Glass, or Frost and an accent color. The choice is saved in the app data settings file. Bundled licenses are in `vendor/platform-tools/NOTICE.txt` and `vendor/7zip/License.txt`.

To rebuild on Windows with the project dependencies installed, run `npm install` and `npm run dist:win`. The build creates the portable `.exe` in `dist/`.

## Run the development preview

1. Install Node.js 20 or newer and Android SDK Platform Tools (ADB).
2. Enable Developer Mode on the headset, connect a USB data cable, and accept **Allow USB debugging** inside the headset.
3. From the repository root, double-click `vr4all.cmd`, or run `node server.js` and open [http://127.0.0.1:4173](http://127.0.0.1:4173).
4. Select the correct headset above Library in the left sidebar. VR4ALL refreshes the list automatically after USB connection. If ADB is not found, use **Connection help** below the headset selector to set the path to `adb.exe`.
5. Open a game card. Choose the latest matching GitHub APK or your local APK, drop each game file onto its field or use **Browse**, then click **Install**. When updating an already installed port, leave the game file fields blank to keep the copies on the headset.

The bottom activity indicator shows live progress for ROM/APK checks, installs, personal builds, headset scans, bulk actions, and GitHub release checks. Bulk installs also show progress at the bottom of their dialog. Success or failure remains visible briefly after the task finishes.

The installer uses `adb -s SERIAL install -r` and `adb -s SERIAL push` so multiple connected headsets are handled separately. The activity panel shows each command’s result. A completed transfer means the files reached the headset; open the game under **Unknown Sources** to confirm it runs.

## How profiles work

The built-in catalog has **94 game cards and 98 port profiles**. The latest research added 22 distinct games and grouped four alternate ports under existing cards: DR-89 Time Crisis I and II, Gen1Recomp, and Mjolnir. Open one of those cards to choose the developer's port; each choice keeps its own APK source, game-file rules, and installed status. Browse by console or genre. Each card shows the original game title with real local artwork sourced in [docs/art-sources.md](art-sources.md). Some ports read ZIPs from `/sdcard/Download/`; others read extracted folders at fixed paths. Each card shows the expected format, destination, and first-launch step. Complex ports link to their official preparation guide when VR4ALL cannot perform the complete setup.

The left sidebar filters **All games**, **Available to install**, and **New games** (the 10 most recent catalog additions). Available to install includes games whose required files have been selected on their cards, plus ports whose APK includes the game files. When a Quest is connected, it also offers **Installed games** and **Update available**. The collection search sorts by A–Z, Z–A, latest release, or **Most downloaded**. Most downloaded orders every visible game by known GitHub release-asset downloads of matching Quest builds; games without a count come last. The **Installed first** checkbox below Sort groups games found on the selected headset above the others, while preserving the chosen sort within each group. It becomes available after a headset scan and remembers its setting. GitHub counts come from cached release checks; use **Check updates** to refresh them. **Check updates** shows GitHub progress and saves per-game results to `%APPDATA%\vr4all\update-checks.txt`. **Scan connected headset** checks installed packages and game data. **Bulk install new games** offers checkboxes for games absent from the Quest using files already selected on their cards. **Update all installed games** appears above the cards in every library view when the selected headset has a confirmed newer APK for any installed port. It updates eligible games across the full library, regardless of the current filter. Clicking it rechecks releases, then updates eligible games one at a time with a spinner and current-game progress below the button. Existing game data on the Quest is reused. Local ROM and APK selections are remembered by path rather than copied. Some disc images and arcade sets can only be checked by format, so use the matching game files before installing.

ZIP game-file fields also accept `.7z`, `.rar`, a folder, or multiple loose files. Use **Browse folder** or drop a folder or several files on that game's field. VR4ALL places the contents at the ZIP root, preserves nested paths, validates the resulting ZIP, and remembers the original source path for later installs. The Windows EXE bundles the converter. VR4ALL rejects links, unsafe paths, more than 5,000 entries, and contents over 8 GB; it also rejects password-protected source archives. The ZIP check confirms structure, not the identity of the ROM set inside it. Single-file fields accept the required ROM, disc image, CHD, BIOS, or APK directly, or one inside a ZIP, 7z, or RAR. VR4ALL identifies a single matching member, extracts it for installation, and rejects ambiguous archives. Creator installer workflows also accept archived owned game folders where their original data layout is present.

Use **Request a port** in the sidebar to suggest a missing standalone Quest mod on GitHub. To change a game's release source, open its card and choose **Edit GitHub source**; enter `owner/repository` and a filename pattern that matches only that port's Quest APK. VR4ALL remembers absolute paths for browsed and dropped local game files. **Forget** removes a remembered link without deleting the original. If you move or delete a file, choose it again on its game card. VR4ALL does not supply commercial game files. Existing personal custom ports remain in your local library after an update, although the Add a port shortcut is no longer shown.

Open a game card and choose or drop each required ROM, game folder, or local APK there. VR4ALL checks it and remembers its original path. **Bulk install new games** then shows those saved choices with checkboxes, one Install button, and Forget buttons for saved paths. It does not scan Downloads or automatically assign files from any folder. The browser development preview must stage dropped bytes temporarily because a web page cannot read their filesystem paths; those staged drops are only available during that session. Generated ZIPs and build outputs use temporary work locations as needed. Older managed copies from previous versions are left untouched; where possible, VR4ALL restores the original path from their saved metadata. Failed job details are saved in `%APPDATA%\vr4all\install-jobs.txt` for troubleshooting without a Recent failures panel in Bulk install.

VR4ALL checks the official GitHub release assets for linked profiles and selects each profile's matching Quest file. It caches results for 15 minutes and falls back to the public release page when the unauthenticated API is rate limited. Clicking **Download & install** downloads the current matching APK, installs it over the existing app, and transfers any newly selected game data. When the package is already installed with its game data on the selected Quest, empty game file fields leave those files in place. Pokémon Gen 1 VR caches its selected ROM privately, so VR4ALL permits an APK update without supplying the ROM again but cannot confirm the cache from the headset scan. Road Rash and Harry Potter use official installer ZIPs; VR4ALL now runs their authors' player installers with the selected Quest and the user's owned game files. Neither flow was tested end to end with original discs/game data here. Some updates have special migration requirements; read the release page shown in the card before upgrading.

Descent 3 VR now installs the official Quest APK and copies HOG files plus missions and movies from an owned PC game folder. JKXR now installs the official engine and Meta companion APKs, then copies the required archives from an owned Jedi Outcast or Jedi Academy folder. Bulk update checks official releases before enabling GitHub-based updates; a failed or stale check appears beside the game instead of starting an install. The release fallback retries GitHub pages that temporarily return an empty release list.

For the selected connected Quest, VR4ALL reads installed package versions and checks required game-file locations. A **green outline** means the data check passed and the installed APK matches a fresh checked GitHub release. **Orange** indicates a different checked APK or a newer comparable version. **Blue** means the package is installed but its release version cannot be confirmed; each card and detail panel explain the reason. Missing required game data is shown separately. When GitHub publishes a SHA-256 digest, VR4ALL checks the installed APK bytes and uses an exact match ahead of the app's manifest version; this fixes ports such as Perfect Dark that report a fixed `versionName=1.0` across later releases. Mega Man 64's data check recognizes the ROM after the port imports and renames it. Mario Kart Wii stays blue because its installed APK differs from the official release and the version schemes are not comparable. No updates are installed automatically.

A **purple outline** and **Install available** label mean the required files selected on that game card are ready for installation on the selected Quest. The app remembers their original paths across restarts. If two ports request the same named file in the same format and headset location, choosing it once also fills the other card. This covers the Namco board ROM, shared NAOMI BIOS, and files used by both Maze of the Kings ports. Forgetting a shared choice clears its links from those cards without deleting the original file. A similarly named but different file, such as Rave Racer’s `c71.bin` BIOS, stays separate from `namcoc71.zip`.

In the desktop EXE, dropped files stay in their original locations and VR4ALL remembers their paths. The browser preview stages dropped bytes temporarily. Game folder fields accept the installed game folder or a ZIP, 7z, or RAR of that folder. VR4ALL scans archive contents, extracts to a temporary work folder for installation, and keeps the original archive path for later use. For Amnesia, an archive containing only the PC installer is rejected because it lacks the required `config`, `maps`, and `entities` game folders. Once the Sclerosis APK and those folders are found on the Quest, its card shows Ready even while the creator APK remains saved on your PC; creator APK updates are still downloaded manually. VR4ALL checks extensions and file signatures before installation; known Nintendo 64 games are also checked against cartridge title codes. This does not establish an exact ROM revision or independently verify every arcade ZIP's contents.

The [build and patch inventory](build-required.md) records ports that need an author build or patch workflow. GTA: San Andreas, Red Dead Redemption, and Vice City cards run the authors' personal build scripts from complete owned game files. GTA SA also needs the separate supported audio pack. VR4ALL pins the source commit, keeps per-game build folders for updates, and targets the selected Quest. First builds may download several GB of tools and require Android SDK licenses; these builds were not run end to end here because the required owned games were unavailable. Crazy Taxi accepts the exact compatible owned Android `.apkm`, checks the published xdelta patch, and uses the compatible xdelta3 command-line decoder locally before installing; the app links to the author-recommended DeltaPatcher GUI as well. Doom3Quest and Quake3Quest use official GitHub APKs: select the original Doom 3 `base` folder or Quake III `baseq3` folder, and VR4ALL checks named PK4/PK3 files before copying it.

Beef Raider XR now has a verified Quest APK in the author's GitHub release. VR4ALL installs the demo from that APK. For the full Tomb Raider game, use the author's desktop extraction tool on your owned files, launch the headset app once to grant permissions, then drop the tool's `mod` folder with `Audio`, `FMV`, and `DATA` into VR4ALL. The app checks and transfers those folders to the selected Quest. The extractor's GUI has no verified unattended interface, so extraction itself remains a separate step.

Half-Life 1 appears as **Lambda1VR**. It uses a prebuilt Quest engine and your owned Half-Life `valve` folder, so no PC APK build is needed. Half-Life 2 appears as **SourceVR**: it publishes a Quest APK but needs the matching owned Steam game folders on the headset. A separate experimental Half-Life 2 port uses a PC cache-building workflow and is tracked in the research inventory.

The [port inventory](../PORTS.md) and [standalone research report](standalone-port-research.md) list more candidates, including several Team Beef projects that need multi-APK installation or a more specific data-import flow. The catalog is growing and is not a complete census of every standalone VR port.

## Integrated installers and game details

RDR and GTA SA include **Export game from phone** above the game-file field. Install your supported Android edition on an ARM64 phone or tablet (Google Play or Netflix for RDR; Google Play for GTA SA), open it and finish its downloads, then enable USB debugging and approve this PC. In VR4ALL choose the source phone and where to save the export, then select **Export game**. The app checks free space, copies all installed APK splits, verifies their SHA-256 checksums against the phone, and checks for the ARM64 engine and required game data. It creates a separate folder on the chosen drive and automatically selects it as your game input. Disconnect the phone and connect your Quest before building. Phones are listed separately from headset install targets. This flow reads the phone without installing or changing its apps. The official builder still checks signatures and engine compatibility afterward.

Built-in phone export supports Google Play and Netflix RDR `1.58.63226194`, plus Google Play GTA SA `2.11.311`. RDR detects the installed edition automatically; use the edition selector when both are installed. Either RDR edition can keep downloaded game packs in private app storage. A Google Play installation on an SM-S911W was verified to expose only `base.apk`, `split_data0.apk` and `split_data1.apk`, while its playable game still needed seven resources absent from those APKs. Buying another edition does not guarantee a complete export without root. The official builder still determines whether the exported engine is compatible; the version number alone does not guarantee this.

The RDR export window automatically checks the selected phone and offers **Check phone** to repeat the check. When Android supports ZIP listing, VR4ALL reads APK directory entries on the phone before copying game files. It reports whether the required data entries are present, need your selected supplemental source, or are missing without readable private storage. A known missing-data case stops before the large transfer. Existing root tooling is detected without requesting superuser access during preview; authorization and file verification happen only during export. If Android cannot provide a compatible listing, the result is explicitly unknown and you can proceed with the existing copy-and-verify method. The app never decides completeness from the edition or number of APKs, and the preview does not establish engine compatibility or data authenticity.

For RDR, **Additional RDR game data (if export is incomplete)** accepts matching world, cutscene and audio resources, about 3.7 GB. The phone-export window shows this selection directly, restores your saved source, and rechecks when you select a data archive or folder. Use a local archive or folder containing `split_game0.apk` through `split_game3.apk`, or the author's raw `asset-packs/<pack>/assets/game/...` layout. Users without readable private packs must already have matching files or a complete export from a device that can read the packs; this remains a requirement, not an automatic download feature. The export activity records the selected source so missing-data failures can be distinguished from transfer failures. VR4ALL imports only `.rpf` and `.bk2` game resources from this input, retains your original phone APK code, and remembers the source location. It checks required file presence, copy hashes, unsafe archive paths and free space; these checks do not establish the source's authenticity. A complete export needs no additional input. Temporary files stay on the selected export/build drive. VR4ALL does not include, host or download these commercial game assets, and there is currently no official standalone resource download configured in the app.

Without a selected additional data source, VR4ALL checks for existing root access when either RDR edition's APKs are incomplete, then streams that edition's private packs to the selected PC folder. It verifies size and SHA-256 and saves the builder's `asset-packs` layout. If the phone cannot read those private files, export stops with instructions to select matching data or a complete export. VR4ALL does not root the phone or change its files. GTA SA's audio pack remains a separate required input.

Before RDR builds, VR4ALL checks the selected Quest's current internet connection. Connect the headset to Wi-Fi with working internet and keep it online during first launch and Netflix sign-in. If connectivity diagnostics are unavailable, the app shows a reminder and continues. An offline headset can fail Widevine provisioning with NGP-92 even after a successful installation. Check the Quest's internet connection, fully close RDR and reopen it before repeating an export or reinstalling.

GTA: San Andreas offers the same **Set up build tools** screen as RDR and Vice City. Choose where to keep the downloads, review any required Google licenses, then build using your owned game export and the required audio pack. Tool setup itself does not need either game input or a connected headset.

The GTA SA audio field includes **Download required audio pack**. On the linked page, choose **Original plan mod pack** (1.41 GB), named `gta-sa-ps2-style-mod-pack_1786856007_737162.7z`. Save it beside your game files, then choose or drop that archive in the audio field; extraction is automatic. The download opens in your browser because the site generates its download links there.

Red Dead Redemption also offers **Set up build tools** before building. Choose a drive with free space, review each Google license prompt in the app, and complete setup before choosing **Build and install**. RDR uses its own SDK requirements, including Android build-tools 35.0.0. A failed build reporting unaccepted SDK licenses needs this setup step; VR4ALL does not accept licenses automatically.

RDR and GTA SA accept APKM game containers by preparing a temporary ZIP in the selected build folder. A hard link avoids copying the whole archive when the filesystem supports it; otherwise VR4ALL uses a temporary copy. 7z and RAR game containers are converted there too, and temporary preparation files are removed after the build. The original selected file remains unchanged. RDR still needs all of its game data: either edition's APKs can omit downloaded world and audio packs. VR4ALL's phone export and the author's `EXPORT_RDR_APKS.bat` can export private packs using existing root access into an `asset-packs` folder; select that complete export folder for the build.

Vice City, RDR and GTA San Andreas ask for a **Download folder** before setting up their build tools. The first setup defaults to your selected game folder, or the folder containing your game archive. Later games default to the saved tools location so compatible tools can be reused. Choose another drive with Browse or paste a folder path, then select **Download and set up tools**. VR4ALL keeps shared tools and downloads in `VR4ALL-build-tools/builds/shared` there, with separate source kits and game build output. Java 21, Android 35, NDK 27.2.12479018 and CMake 3.22.1 are shared; Vice City's build-tools 34.0.0 and the other games' 35.0.0 coexist. Existing tool folders at that location are adopted without downloading again. Conflicting older files are preserved in a `.previous-...` folder and recorded in Activity. Choosing a different download folder creates a separate cache at that location. Review any new Google licenses in the same window, then choose **Build and install**. Opening or closing the location screen starts no downloads.

Survivor 2 - Code: Veronica VR has its own Arcade / Shooter card and downloads the Quest APK from [its releases](https://github.com/vr4all-standalone/survivor2-code-veronica-vr/releases). Supply your owned NAOMI World BHF2 Ver. E `gunsur2.zip` with all 15 cartridge ROMs. VR4ALL copies it to `/sdcard/Download/gunsur2.zip`; a separate `/sdcard/Download/naomi.zip` is optional when a supported BIOS is embedded. No CHD or PIC is required. Japanese `gunsur2j` revisions are unsupported. The port checks ROM lengths and CRC metadata before Play; this does not certify compressed payload integrity. The headset scan checks file presence. It supports one player per app instance, left-stick movement, right-stick snap turns and a tracked gun that either fresh trigger can take. Reload follows the native game and Wider view is unavailable. The weapon update prepares eight complete native weapon models locally from your own cartridge. Choose **Gun → In-game weapons** for automatic swaps; B or Y skips preparation for that session. The user reports successful headset gameplay on preview 1; physical testing of the weapon update, later stages and both full character routes remain open.

Death Crimson OX VR has its own Arcade / Rail shooter card and downloads only `death-crimson-ox-vr-quest.apk` from [its project releases](https://github.com/vr4all-standalone/death-crimson-ox-vr/releases). Supply your complete owned Japan Rev A cartridge ZIP: `epr-23524a.ic22` (CRC `b60e113e`) and ten 8 MiB MPR ROMs. VR4ALL copies it to `/sdcard/Download/deathcoxj.zip`; an older merged `deathcox.zip` containing these Rev A ROMs can be selected and is copied separately to that canonical name. Current USA `deathcox` and original Japan `deathcoxo` are unsupported. A separate `/sdcard/Download/naomi.zip` is optional when a supported BIOS is embedded in the game ZIP. No CHD is required. The port checks actual ROM and BIOS bytes, lengths and CRCs before Play; VR4ALL's headset scan checks the canonical ZIP's presence. The Two players setting defaults to P1 left / P2 right; solo play can use either trigger with independent hand transfer. First launch prepares the native soldier pistol from the owned cartridge, and B or Y skips it. This is experimental and physical headset testing remains pending.

F-Zero X uses only the [Virtua VR Port Quest R10 installer](https://virtuavrport.itch.io/f-zero-x-vr). Download **Standalone Quest — Install using Windows PC (R10)** there, then provide its complete ZIP or extracted folder and your exact US Rev 0 `.z64` ROM. VR4ALL verifies both inputs, runs the included Windows ROM extractor, installs its Quest APK, and transfers the three prepared files. The creator package must be supplied manually once; VR4ALL remembers its path. The preparation was verified with a local R10 package and a simulated transfer to the selected headset; in-game graphics still need confirmation on a connected Quest.

Opening a game docks its details beside the library. **Change theme** also opens the appearance and setup panel, where you can select the original slide-over panel or a focused game view. Creator-hosted ports such as Rave Racer, Sclerosis, WolfSharp, and Hexen II show a manual APK download explanation instead of a disabled GitHub update choice. Drop the creator APK once and VR4ALL remembers its original path for later installs; these ports cannot be auto-updated from GitHub unless the author publishes a verified release source. If an install fails, read its Activity log, correct the input or headset connection, and choose **Retry install** on the same selected Quest. **Report a bug** opens the GitHub form; remove ROMs, serial numbers, and private file paths from any log excerpt you submit.

The integrated installers run the authors' packaged Quest installers for Descent 1 & 2, Gothic II, GT2, and Animal Crossing. Magic Carpet uses its official Windows importer; GalaxyQuest uses its official Windows converter; AstroQuest accepts the author's required extracted CUSA12392 folder; Sclerosis accepts a creator APK and an owned Amnesia folder. QuestZDoom and RazeXR install their engine and launcher APKs together. Tiberian Dawn MR installs its Quest Spatial APK and places both owned disc ISOs for its in-headset importer. Gothic II and Tiberian Dawn still need the user to choose the prepared files inside the headset; AstroQuest does not accept an encrypted PS4 package or raw disc. See [the integrated installer notes](integrated-installers-2026-10-22.md).

## Development

The browser preview needs no npm install. Run `node --test` for tests and `node --check public/app.js` for a JavaScript syntax check. The preview server binds to `127.0.0.1:4173`; the desktop app chooses a free loopback port. Both require a random per-run token for changes. Neither calls a shell with user-entered paths.
